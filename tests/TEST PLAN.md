# Stills & Reels: test plan (must all pass before a build is handed over)

Automated, run on Linux (Mono, Xvfb, system FFmpeg). `tests/run.sh all` builds the app and runs every test below except the recording sync tests (8 to 13), which are run by hand as described at the top of `tests/AvSyncTest.cs`. `tests/run.sh <name>` runs one; the names are in BUILD NOTES.txt.

Tests 8–10 also check that the sound lasts to within 0.1 s of the last frame, in each part and in the finished MP4.

Tests 8–10 are each run 3 times. They all must pass every time.

What Linux can't cover for 2.4: the WM_TIMER starvation itself (the playhead that stood still is a Windows message-queue effect that Mono's loop doesn't reproduce, so test 16 proves the new path works but not that the old one failed). Those are in "Windows checks.md".

What Linux can't cover for 2.3: the taskbar jump list itself (Windows shell COM), real taskbar entries and grouping, Opacity hiding the Snip window during the timer (Mono under Xvfb has no compositor), and focus handover from a second copy. Those are in "Windows checks.md".

What Linux can't cover: gdigrab itself, Windows loopback capture of real PC sound (WASAPI) and dshow microphones. Those are in "Windows checks.md".

What Linux can't cover for pictures in 3.0: real GDI+ drawing and text on Windows (Mono's libgdiplus differs in places), HEIC photos from a phone (the test FFmpeg here is 6.1, which can't read them; the bundled 7.1 can, and the tile and way-up handling is tested with stand-in files only), the list of real windows for a window snip (Windows API), more than one monitor, and screens set to 125% or 150%. Those are in "Windows checks.md".

What Linux can't cover for video in 3.0: the graphics-card encoders (NVIDIA, Intel, AMD: the Linux test FFmpeg has none, so only the fall-back path is tested), the recovery prompt at start-up (skipped under Mono unless `SR_RECOVERY` is set) and hard links for recovery media, the bundled FFmpeg 7.1's versions of the sound filters (the tests use 6.1), multi-core speed on the user's own processor, and how the level meter, fade handles and export window look at 125% or 150%. Those are in "Windows checks.md".
